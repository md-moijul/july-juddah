## 1.3: Serverless PDF Generation Endpoint

**Status:** Done

**Story:**
**As a** system, **I want** to have a serverless endpoint that receives user details, **so that** I can generate a high-resolution, non-editable PDF certificate.

**Acceptance Criteria:**
1.  A new serverless function (e.g., `/api/generate-pdf`) is created.
2.  The function accepts a `fullName` and `location` in the request body.
3.  The function uses a PDF generation library and the official certificate template to create a high-resolution PDF.
4.  If the function is called successfully with valid data, it returns a `200 OK` status and the PDF file in the response.
5.  The returned PDF file is correctly populated with the `fullName` and `location` data.
6.  The function handles errors gracefully, returning an appropriate error code (e.g., `400 Bad Request` for missing data).

**Dev Notes:**
*   **Previous Story Insights**: The frontend is set up to accept user input. This story will create the backend to process that input.
*   **Data Models**:
    *   `CertificateData` interface:
        ```typescript
        export interface CertificateData {
          fullName: string;
          location: string;
        }
        ```
        [Source: docs/architecture/data-models.md]
*   **API Specifications**:
    *   The backend will implement the `POST /api/generate-pdf` endpoint.
    *   Request body must match the `CertificateData` schema.
    *   Successful response will be `200 OK` with `application/pdf` content.
    *   Error responses will be `400 Bad Request` or `500 Internal Server Error` with a JSON error message.
    [Source: docs/architecture/api-specification.md]
*   **Component Specifications**:
    *   No new frontend components in this story.
*   **File Locations**:
    *   The serverless function will be located at `apps/web/src/app/api/generate-pdf/route.ts`. [Source: docs/architecture/backend-architecture.md#service-architecture, docs/architecture/unified-project-structure.md]
*   **Testing Requirements**:
    *   Unit tests should be written for the serverless function.
    *   Tests should cover successful PDF generation, error handling for missing data, and correct data population in the PDF.
    [Source: docs/architecture/testing-strategy.md]
*   **Technical Constraints**:
    *   **Backend Language**: TypeScript [Source: docs/architecture/tech-stack.md]
    *   **Backend Framework**: Next.js API Routes [Source: docs/architecture/tech-stack.md]
    *   **PDF Generation Library**: A suitable library for Node.js environment needs to be chosen and added as a dependency. `pdf-lib` is a good candidate.
