# Story 4.6: Implement Backend Logic for Order Fulfillment

**Status:** Draft

**Story:**
As an admin, I want to receive a notification with the user's details when they confirm an order for a hard copy, so that I can process and ship their certificate.

**Acceptance Criteria:**
1.  The "Confirm Order" button on the `/purchase` page is initially active.
2.  Clicking "Confirm Order" triggers a backend API call.
3.  The API call saves the user's phone number and address to the `orders` table in the database, linked to their certificate.
4.  Upon successful submission, the backend triggers an action for order fulfillment (e.g., sends a formatted email to an admin address).
5.  The fulfillment email contains all necessary details: Certificate Number, User Name, Shipping Address, Phone Number.
6.  After clicking "Confirm Order", the user is shown a confirmation message on the screen (e.g., "Thank you! Your order has been placed.").
7.  The "Confirm Order" button becomes disabled after a successful submission to prevent duplicate orders.

**Tasks / Subtasks:**
- [ ] Create a new API endpoint (e.g., `/api/create-order`).
- [ ] The endpoint should accept `certificate_id`, `phone_number`, and `full_address`.
- [ ] Implement the logic to create a new record in the `orders` table.
- [ ] Implement the email sending logic. Configure an email service (e.g., SendGrid, Resend).
- [ ] Create an HTML template for the order notification email.
- [ ] Connect the `/purchase` page's "Confirm Order" button to this new endpoint.
- [ ] Implement the success state UI on the `/purchase` page.

**Dev Notes:**
- Using a transactional email service is recommended for reliability.
- Ensure sensitive information like admin email addresses are stored in environment variables.
- The webhook alternative is also viable if a more automated fulfillment system is planned for the future.
