### Story
**As a** user,
**I want** to enter my phone number, accept the terms, and confirm my action on the "Download E-certificate" tab,
**so that** I can securely trigger the download of my digital certificate.

### Acceptance Criteria
1.  The "Download E-certificate" tab panel (`EcertificateTab`) is implemented with the required UI components.
2.  The panel contains an `Input` for the phone number, a `Checkbox` for "Terms & Conditions", a placeholder `div` for a CAPTCHA, and a "Confirm & Download" `Button`.
3.  The "Confirm & Download" button is disabled until a valid phone number is entered, the Terms & Conditions are accepted, and the (placeholder) CAPTCHA is considered complete.
4.  The button's `onClick` handler correctly calls the Server Action defined in Story 5.2, passing the user's `name`, `town`, and `phone` number.
5.  **On a successful response** from the Server Action (`{ success: true }`), the client-side logic initiates the PDF download.
6.  **On a failure response** from the Server Action indicating a duplicate phone number (`{ success: false, error: '...' }`), a specific error message is displayed next to the phone number input field.
7.  State is managed for all interactive elements, including loading and error states during the API call.

### Dev Notes
-   **Component Structure:** This story focuses exclusively on the `EcertificateTab` component. The primary task is to build out its UI and client-side logic.
-   **State Management:** Use React's `useState` hook to manage the form's state, including the phone number, checkbox status, CAPTCHA verification status (can be a mock state for now), and the loading/error states for the API call.
-   **Server Action:** The "Confirm & Download" button's `onClick` handler will directly invoke the Next.js Server Action created in Story 5.2. This action handles the backend logic of checking for duplicate phone numbers and creating a certificate record.
-   **Data Flow:** The `name` and `town` values are expected to be passed down as props from the parent `/generate` page component. The `phone` number will be managed within the `EcertificateTab`'s local state.
-   **Error Handling:** The Server Action provides a specific error message for when a phone number already exists. The UI must display this exact message to the user, ideally next to the phone input field to provide clear context.
-   **CAPTCHA Placeholder:** The `div` for the CAPTCHA is a placeholder for future integration. For this story, you can simulate its completion state with a `useState` hook that is initially `true` or toggled with a temporary button.
-   **PDF Download:** The actual PDF generation is handled by a separate process. This story's responsibility is to trigger the download on a successful response from the Server Action. This can be done by creating a dynamic link or using a library like `js-file-download`.
