# Story 8.4: Refactor CertificateForm Component

**Status:** Draft

**Epic:** [Refactor User Data and State Management](docs/prd/epic-8-refactor-user-data-and-state-management.md)

**Story:** As a developer, I want to refactor the `CertificateForm` component to be responsible only for capturing the user's name and district, to simplify its logic and improve component reusability.

**Acceptance Criteria:**

1.  The `CertificateForm` component is modified to only contain input fields for `name` and `district`.
2.  All logic related to the phone number input and the `createUser` action is removed from this component.
3.  The component continues to get its initial values from the `UserDataContext`.

**Tasks / Subtasks:**

-   [ ] Open the file for the `CertificateForm` component.
-   [ ] Remove the phone number input field and any associated state and validation logic.
-   [ ] Remove the "Confirm & Download" button and its `onClick` handler.
-   [ ] Ensure the `name` and `district` input fields are still correctly pre-populated from the `useUser` hook.

**Dev Notes:**

*   This is purely a refactoring story. The goal is to make the `CertificateForm` a simpler, more focused component.

**Testing:**

*   Manually verify that the form renders correctly with only the `name` and `district` fields and that they are pre-populated if a user is in the context.
