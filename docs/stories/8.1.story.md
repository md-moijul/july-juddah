# Story 8.1: Foundational UserDataContext

**Status:** Done

**Epic:** [Refactor User Data and State Management](docs/prd/epic-8-refactor-user-data-and-state-management.md)

**Story:** As a developer, I want to create a foundational `UserDataContext` so that I can provide a centralized and reusable state management solution for user data across the application.

**Acceptance Criteria:**

1.  A new file, `apps/web/src/context/UserDataContext.tsx`, is created.
2.  The file defines and exports a `User` interface: `{ id: string; name: string; town: string; phone: string; }`.
3.  The file defines and exports a `UserDataContext` using React's `createContext`.
4.  The file defines and exports a `UserDataProvider` component that manages the `user` object and a `loading` state.
5.  The file defines and exports a `useUser` custom hook for easy consumption of the context.
6.  The implementation must not be integrated into any page yet; it should only contain the context logic.

**Tasks / Subtasks:**

-   [x] Create the directory `apps/web/src/context`.
-   [x] Create the file `apps/web/src/context/UserDataContext.tsx`.
-   [x] In the new file, define and export the `User` interface with the following properties: `id: string`, `name: string`, `town: string`, `phone: string`.
-   [x] In the same file, create and export the `UserDataContext` using `createContext`. The context should have a default value that includes a `user` object (initially `null`), a `loading` state (initially `true`), and a `setUser` function.
-   [x] In the same file, create and export the `UserDataProvider` component. This component will use the `useState` hook to manage the `user` and `loading` states and provide them to the context.
-   [x] In the same file, create and export the `useUser` custom hook. This hook will use the `useContext` hook to access the `UserDataContext` and return its value.

**Dev Notes:**

*   This is a foundational story. No visual changes are expected.
*   The `UserDataProvider` should initialize with a `null` user and `loading` as `true`.
*   The `useUser` hook should throw an error if used outside of a `UserDataProvider` to ensure it's used correctly.

**Testing:**

*   No automated tests are required for this story, but the code should be well-structured and typed with TSDoc comments explaining the purpose of the context, provider, and hook.
