# Story 8.3: Integrate Zustand Store on Generate Page

**Status:** Done

**Epic:** [Refactor User Data and State Management](docs/prd/epic-8-refactor-user-data-and-state-management.md)

**Story:** As a user, I want the `/generate` page to automatically load my data if I have visited before, so that I don't have to re-enter my information every time.

**Acceptance Criteria:**

1.  The `GeneratePage` component is wrapped with the `ZustandProvider`.
2.  On page load, a `useEffect` hook checks local storage for a `userId`.
3.  If a `userId` exists, the `getUserById` action is called, and the `ZustandStore` is updated with the fetched user data.
4.  The form inputs for `name`, `town`, and `phone` are pre-populated with the data from the `ZustandStore`.
5.  After a new user is successfully created via the `createUser` action, the new `userId` is saved to local storage.
6.  All legacy code that reads or writes the full user object to/from local storage is removed.

**Tasks / Subtasks:**

-   [x] Open the file `apps/web/src/app/generate/page.tsx`.
-   [x] Import the `useUserStore` from `~/stores/useUserStore`.
-   [x] Wrap the main return statement of the `GeneratePage` component with the `<ZustandProvider>`.
-   [x] Inside the `GeneratePage` component, add a `useEffect` hook with an empty dependency array to run on component mount.
-   [x] Inside the `useEffect`, read the `userId` from local storage. If a `userId` is found, call the `getUserById` server action with the `userId`.
-   [x] When the `getUserById` action returns user data, update the `ZustandStore` with the fetched data.
-   [x] Refactor the form input components (`name`, `town`, `phone`) to get their values from the `useUser` hook.
-   [x] In the success handler for the `createUser` server action, save the `id` of the newly created user to local storage under the key `userId`.
-   [x] Search the codebase and remove any code that reads or writes user data (other than the `userId`) to local storage.
