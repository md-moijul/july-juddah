# Story 8.3: Integrate UserDataContext on Generate Page

**Status:** Draft

**Epic:** [Refactor User Data and State Management](docs/prd/epic-8-refactor-user-data-and-state-management.md)

**Story:** As a user, I want the `/generate` page to automatically load my data if I have visited before, so that I don't have to re-enter my information every time.

**Acceptance Criteria:**

1.  The `GeneratePage` component is wrapped with the `UserDataProvider`.
2.  On page load, a `useEffect` hook checks local storage for a `userId`.
3.  If a `userId` exists, the `getUserById` action is called, and the `UserDataContext` is updated with the fetched user data.
4.  The form inputs for `name`, `town`, and `phone` are pre-populated with the data from the `UserDataContext`.
5.  After a new user is successfully created via the `createUser` action, the new `userId` is saved to local storage.
6.  All legacy code that reads or writes the full user object to/from local storage is removed.

**Tasks / Subtasks:**

-   [ ] Wrap the `GeneratePage` component in `UserDataProvider`.
-   [ ] Implement the `useEffect` hook for data fetching.
-   [ ] Call `getUserById` and update the context.
-   [ ] Refactor form inputs to use the `useUser` hook.
-   [ ] Update the `createUser` success handler to save the `userId`.
-   [ ] Remove old local storage logic for `user` object.

**Dev Notes:**

*   This story ties together the work from stories 8.1 and 8.2.
*   Pay close attention to the loading state to prevent UI flickering.

**Testing:**

*   Manually test the following scenarios:
    *   First-time visit (no `userId` in local storage).
    *   Returning visit (`userId` in local storage).
    *   Creating a new user and verifying the `userId` is saved.
