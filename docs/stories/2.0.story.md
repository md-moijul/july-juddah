## 2.0: Setup Content and Styling Architecture

**Status:** Done

**Story:**
**As a** developer, **I want** to establish a centralized and decoupled architecture for handling content and styling, **so that** the application is more maintainable, scalable, and easier to update.

**Acceptance Criteria:**
1.  A new file is created at `apps/web/src/lib/content.ts`.
2.  `content.ts` imports the raw JSON data from `docs/assets/content.json`.
3.  `content.ts` defines and uses TypeScript interfaces to enforce a strong type structure for the content.
4.  `content.ts` exports a single, typed `content` object for components to consume.
5.  The `apps/web/tailwind.config.ts` file is modified to import design tokens from `docs/assets/style.json`.
6.  The imported style tokens (e.g., colors, fonts) are programmatically added to the `theme.extend` section of the Tailwind configuration.
7.  Frontend components can access content exclusively through the `content` object from `lib/content.ts`.
8.  Frontend components can use the new theme-based utility classes (e.g., `bg-primary`) for styling.

**Dev Notes:**
*   **Architectural Goal**: The primary goal is to decouple UI components from the raw data structures in the `.json` files. This story establishes the foundational pattern for all other stories in Epic 2.
*   **Content Implementation**:
    *   Create TypeScript interfaces in `apps/web/src/lib/content.ts` that mirror the structure of `docs/assets/content.json`.
    *   Export the imported and typed JSON data as a constant, e.g., `export const content = ...`.
*   **Styling Implementation**:
    *   In `apps/web/tailwind.config.ts`, use a `require()` statement or ES6 import to load `docs/assets/style.json`.
    *   Map the JSON values to the appropriate keys in the `theme.extend` object (e.g., `theme.extend.colors`, `theme.extend.fontFamily`).
*   **File Locations**:
    *   `apps/web/src/lib/content.ts` (new)
    *   `apps/web/tailwind.config.ts` (modified)
    *   `docs/assets/content.json` (source)
    *   `docs/assets/style.json` (source)
*   **Testing Requirements**:
    *   No new unit or component tests are required for this story, as it is primarily a structural setup. Verification will be done by confirming the successful integration in subsequent stories.
