# Story 4.5: Build /purchase Page for Hard Copy Orders

**Status:** Draft

**Story:**
As a user who wants a physical copy of my certificate, I want to navigate to a dedicated purchase page where I can enter my shipping details to place an order.

**Acceptance Criteria:**
1.  Clicking the "Get a Hard Copy" button on the `/generate` page navigates the user to `/purchase`.
2.  The certificate ID or relevant data is passed to the `/purchase` page.
3.  The `/purchase` page displays a form with input fields for "Phone Number" and "Full Address".
4.  The address field should be a textarea to accommodate multi-line addresses.
5.  A "Confirm Order" button is present at the bottom of the form.
6.  The UI of the `/purchase` page is consistent with the rest of the application's design.

**Tasks / Subtasks:**
- [ ] Create a new page route and component for `/purchase`.
- [ ] Implement the navigation from the `/generate` page, passing the generated certificate's ID in the URL or state.
- [ ] Build the UI for the purchase form with phone and address inputs.
- [ ] Add client-side validation for the form fields (e.g., phone number format, non-empty address).
- [ ] Implement state management for the form inputs.

**Dev Notes:**
- Consider how to handle cases where a user navigates directly to `/purchase` without having generated a certificate. They should be redirected or shown an appropriate message.
- The design should be simple and focused on capturing the necessary information efficiently.
