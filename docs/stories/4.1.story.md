# Story 4.1: Setup Backend for Advanced Certificate Generation

**Status:** Draft

**Story:**
As a developer, I want to set up the necessary backend infrastructure, including a database and an OTP service, so that we can support the new features for storing user data and verifying phone numbers.

**Acceptance Criteria:**
1.  A database schema is designed and created to store user information (name, phone number, address) and certificate details (unique certificate number).
2.  The project is configured to connect to a Vercel Postgres database instance.
3.  An SMS OTP service (e.g., Twilio, Vonage, or a similar provider) is integrated into the backend.
4.  An API endpoint is created to send an OTP to a given phone number.
5.  An API endpoint is created to verify the OTP submitted by the user.
6.  The database schema includes a table for certificate orders.

**Tasks / Subtasks:**
- [ ] Research and select an appropriate SMS OTP provider.
- [ ] Configure environment variables for database connection and OTP service credentials.
- [ ] Create a new database table `certificates` with columns for `id`, `user_name`, `district`, `certificate_number`, `phone_number`, `created_at`.
- [ ] Create a new database table `orders` with columns for `id`, `certificate_id`, `full_address`, `status`, `created_at`.
- [ ] Implement a backend function to generate a unique, sequential certificate number.
- [ ] Implement the `/api/send-otp` endpoint.
- [ ] Implement the `/api/verify-otp` endpoint.

**Dev Notes:**
- Ensure the OTP service has a free tier suitable for development and testing.
- The database choice is Vercel Postgres as per requirements, ensure the setup is compatible with the existing Vercel deployment.
