## 1.4: Finalize Download Integration

**Status:** Done

**Story:**
**As a** participant, **I want** to click the download button and receive my finalized PDF certificate, **so that** I have a permanent digital memento of my achievement.

**Acceptance Criteria:**
1.  The "Download PDF" button on the `/generate` page is now functional.
2.  Clicking the button triggers a client-side call to the `/api/generate-pdf` serverless endpoint, passing the current "Full Name" and "Location" from the input fields.
3.  Upon a successful response from the API, the browser automatically initiates a download of the PDF file.
4.  The downloaded file is named logically using the participant's name (e.g., `July_Revelation_Certificate_John_Doe.pdf`).
5.  While the PDF is being generated, a loading indicator is displayed to the user.
6.  If the API call fails, a user-friendly error message is displayed.

**Dev Notes:**
*   **Previous Story Insights**: The backend endpoint `/api/generate-pdf` is complete and functional. This story focuses on integrating the frontend with this endpoint.
*   **Data Models**:
    *   The frontend will use the `CertificateData` interface when making the API call. [Source: docs/architecture/data-models.md]
    ```typescript
    export interface CertificateData {
      fullName: string;
      location: string;
    }
    ```
*   **API Specifications**:
    *   The frontend will call the `POST /api/generate-pdf` endpoint.
    *   The request body must match the `CertificateData` schema.
    *   A successful response will be a `200 OK` with `application/pdf` content.
    *   Error responses will be handled and displayed to the user.
    [Source: docs/architecture/api-specification.md]
*   **Component Specifications**:
    *   The existing "Download PDF" button in the `CertificatePreview` component will be made functional.
*   **File Locations**:
    *   The logic for the API call will be in `apps/web/src/app/generate/page.tsx`. [Source: docs/architecture/frontend-architecture.md]
    *   A new service function `generateCertificatePdf` will be created in `apps/web/src/services/certificateService.ts` to handle the API call. [Source: docs/architecture/frontend-architecture.md]
*   **Testing Requirements**:
    *   Unit tests should be written for the new `generateCertificatePdf` service function.
    *   Component tests for the `/generate` page should be updated to mock the API call and verify:
        *   The loading indicator is shown.
        *   The download is triggered on success.
        *   An error message is shown on failure.
    [Source: docs/architecture/testing-strategy.md]
*   **Technical Constraints**:
    *   Use the browser's `fetch` API for the client-side request.
