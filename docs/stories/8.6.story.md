# Story 8.6: Backend - Create createOrder Server Action

**Status:** Done

**Epic:** [Refactor User Data and State Management](docs/prd/epic-8-refactor-user-data-and-state-management.md)

**Story:** As a developer, I want to create a `createOrder` Server Action that can find or create a user and then create an associated order record, to handle the backend logic for hard copy orders.

**Acceptance Criteria:**

1.  A new server action `createOrder` is created and exported from `apps/web/src/app/actions/user.ts`.
2.  The action accepts `name`, `town`, `phone`, and `shippingAddress` as input.
3.  The action first queries the database to see if a user with the given phone number already exists.
4.  If the user does not exist, a new user is created with the provided data.
5.  A new record is created in the `orders` table, containing the `shippingAddress` and linked to the user's ID.
6.  The action returns the newly created order object on success.
7.  The action returns an error object if the phone number is invalid or if the order creation fails.

**Tasks / Subtasks:**

-   [x] Open the file `apps/web/src/app/actions/user.ts`.
-   [x] Define and export a new asynchronous server action named `createOrder`.
-   [x] The action should accept an object with the following properties: `name: string`, `town: string`, `phone: string`, `shippingAddress: string`.
-   [x] Implement input validation for the phone number. You can reuse the validation logic from the `EcertificateTab` component.
-   [x] Implement the logic to find a user by phone number using the Drizzle ORM.
-   [x] If no user is found, call the `createUser` logic to create a new user.
-   [x] Implement the logic to insert a new record into the `orders` table using the Drizzle ORM.
-   [x] Ensure the new order record is correctly linked to the user's ID.
-   [x] Wrap the user creation and order creation logic in a transaction to ensure data consistency.
-   [x] Return the created order object on success.
-   [x] Return an error object with a descriptive message on failure.

**Dev Notes:**

*   This action should be transactional to ensure data consistency (i.e., if the order creation fails, the user creation should be rolled back if it was part of the same transaction). Drizzle ORM's transaction API should be used for this.
*   Reuse the existing `createUser` logic if possible, but ensure it's integrated into the transaction.
*   The file path for the user actions is `apps/web/src/app/actions/user.ts`, not `apps/web/src/app/actions/user.ts`. Please ensure you are working in the correct file.

**Testing:**

*   Manually test the action to ensure it correctly handles both finding an existing user and creating a new one before creating the order.
*   Test the error handling by providing an invalid phone number.
*   Test the transactional logic by simulating an error during order creation.
