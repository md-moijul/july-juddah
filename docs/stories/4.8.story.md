# Story 4.8: Generate Page Refactor

## Status
Approved

## Story
**As a** user,
**I want** a simplified and persistent certificate generation experience,
**so that** my information is saved and the UI is intuitive.

## Acceptance Criteria
1.  When a user types their name into the "fullName" input, the value is saved to local storage in real-time.
2.  When a user selects a district from the "selectedDistrict" dropdown, the value is saved to local storage in real-time.
3.  When the `GeneratePage` is loaded, if "fullName" and "selectedDistrict" values exist in local storage, the corresponding input fields are pre-populated with those values.
4.  The "Generate Certificate" button is removed from the UI.
5.  The certificate preview updates in real-time as the user types their name or selects a district.
6.  The "Download E-certificate" and "Get a Hard Copy" buttons are disabled by default.
7.  The "Download E-certificate" and "Get a Hard Copy" buttons become enabled only when both "fullName" and "selectedDistrict" have non-empty values.
8.  The `useRouter` hook is removed from the `GeneratePage` component.
9.  The "Get a Hard Copy" button is implemented using a standard Next.js `<Link>` component for navigation.
10. A reusable custom hook `useLocalStorageState` is created to manage the state persistence logic for both "fullName" and "selectedDistrict".
11. The `GeneratePage` is broken down into smaller components: `CertificateForm` and `CertificateDisplay`.

## Dev Notes
- The primary goal of this refactor is to improve the user experience by making the form state persistent and simplifying the UI.
- The introduction of a custom hook and component modularity will improve code quality, reusability, and maintainability.
- Pay close attention to the logic for enabling/disabling the action buttons, as this is a critical part of the new UI flow.
- Ensure all existing functionality (real-time preview, download) remains intact after the refactor.

### Testing
- All new components (`useLocalStorageState`, `CertificateForm`, `CertificateDisplay`) must have corresponding unit tests.
- Test file location: `apps/web/__tests__`
- Test standards: Use Jest and React Testing Library.
- Testing frameworks and patterns to use: Follow existing patterns in the project.
- Specific testing requirements:
  - For `useLocalStorageState`, mock local storage to test reading and writing.
  - For `CertificateForm`, test that user input correctly calls the setter functions.
  - For `CertificateDisplay`, test the button disabled/enabled states and the navigation link.
