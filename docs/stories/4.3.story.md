# Story 4.3: Update PDF Generation Service with Dynamic Data

**Status:** Ready for Review

**Story:**
As a developer, I want to update the backend PDF generation service to use the new certificate template and dynamically insert the user's name, district, and a unique certificate number.

**Acceptance Criteria:**
1.  The PDF generation service loads the new certificate template (`template.pdf`).
2.  The service accepts `name` and `district` as input parameters.
3.  The "[Your Name]" placeholder in the PDF is replaced with the provided `name`.
4.  The "[Town Name]" placeholder in the PDF is replaced with the provided `district`.
5.  A unique certificate number is generated for each request.
6.  The generated certificate number is placed onto the designated area in the PDF.
7.  The service returns the generated PDF as a file or data stream.
8.  The generated certificate data (name, district, certificate number) is saved to the database.

**Tasks / Subtasks:**
- [x] Add the new PDF template `template.pdf` to the project assets.
- [x] Update the PDF library (e.g., `pdf-lib`) code to load `template.pdf`.
- [x] Modify the API endpoint for PDF generation to accept `name` and `district`.
- [x] Implement the logic to find and replace the text placeholders for name and district.
- [x] Integrate the unique certificate number generation logic from Story 4.1.
- [x] Determine the coordinates for placing the certificate number and implement the drawing logic.
- [x] Implement the database insertion logic to save the certificate record upon successful generation.
- [x] Ensure the 'Lora' and 'Inter' font files are embedded into the generated PDF to guarantee correct rendering.
- [x] Implement robust error handling. If the database save fails after the PDF is generated, the operation should fail and an error should be returned to the user.

**Dev Notes:**
- The path to the new template `template.pdf` needs to be correctly resolved. It should be moved to `apps/web/public` or a similar assets folder.
- Font and styling for the dynamic text should match the certificate's design.
- **Text Placement Coordinates (Estimates for `template.pdf`):**
    - **User's Name (`[Your Name]`):** Place at approximately (X: 210, Y: 400) using a 32pt 'Lora' serif font.
    - **District (`[Town Name]`):** Place at approximately (X: 300, Y: 520) within the main text block, using a 14pt 'Inter' sans-serif font.
    - **Certificate Number:** Place at approximately (X: 150, Y: 650) using a 10pt monospace font.
- **Best Practice:** The PDF generation process must use the `certificate-background.png` file as a background layer, and then draw the dynamic text fields on top at the specified coordinates. Do not attempt to "edit" the PDF template directly.
- **Data Source:** The list of 64 districts for the frontend dropdown should be managed in a central data file (e.g., `src/lib/districts.ts`) and not be hardcoded in the UI component.
