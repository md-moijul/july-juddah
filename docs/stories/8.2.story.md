# Story 8.2: Backend - Create getUserById Server Action

**Status:** Done

**Epic:** [Refactor User Data and State Management](docs/prd/epic-8-refactor-user-data-and-state-management.md)

**Story:** As a developer, I want to create a secure `getUserById` Server Action so that the client can fetch the full user object from the database using a `userId`.

**Acceptance Criteria:**

1.  A new server action `getUserById(userId: string)` is created and exported from `apps/web/src/app/actions/user.ts`.
2.  The action securely queries the database to find a user by their `userId`.
3.  The action returns the full user object (`{ id, name, town, phone }`) if the user is found.
4.  The action returns `null` if the user is not found.
5.  The action includes appropriate error handling.

**Tasks / Subtasks:**

-   [x] Open the file `apps/web/src/app/actions/user.ts`.
-   [x] Define and export a new asynchronous server action named `getUserById` that accepts a `userId` of type `string`.
-   [x] Inside the action, use the database client to query the `users` table for a record where the `id` matches the provided `userId`.
-   [x] Add a `try...catch` block to handle potential database errors. In the `catch` block, log the error and return `null`.
-   [x] If a user is found, return the complete user object.
-   [x] If no user is found, return `null`.

**Dev Notes:**

*   This is a backend-only story. No UI changes are expected.
*   The existing database client should be used for the query. The project uses Drizzle ORM, which automatically protects against SQL injection.
*   Ensure the returned user object matches the `User` interface defined in Story 8.1.

**Testing:**

*   The action should be manually tested to ensure it correctly retrieves a user and handles the not-found case. This can be done by creating a temporary test page or by calling the action from a client-side script.
